# Специфікація PDF-документа Pet CV (Pet-Bewerbung)

Цей документ описує **поточну** структуру, вміст і обмеження PDF, згенерованого додатком (`@react-pdf/renderer`). Його можна використовувати як **бриф для дизайну нового шаблону**; після затвердження макету код реалізується в React-компонентах у `src/components/pdf/`.

---

## 1. Технічний контекст

| Параметр | Значення |
|----------|----------|
| Рушій | `@react-pdf/renderer` (React → PDF) |
| Формат сторінки | **A4** (у pt: ширина ~595, висота ~842) |
| Шрифт за замовчуванням | **Helvetica** (вбудований, без завантаження з мережі) |
| Багатосторінковість | Одна сторінка з `wrap`; при переповненні контент може переноситись (залежно від обсягу тексту) |
| Мова дати | Залежить від `data.lang`: `de/fr/it/rm` → відповідні локалі CH, інше → `en-GB` |

**Важливо для дизайну:** кастомні веб-шрифти можна додати через реєстрацію шрифтів у react-pdf (`Font.register`) — зараз цього немає, тому новий шаблон спочатку варто проєктувати під **Helvetica / Times / Courier** (стандартні для PDF).

**Обмеження `@react-pdf/stylesheet`:** числові **`borderRadius: 0`** та **`borderWidth: 0`** проходять через `resolveBorderShorthand` і через `0` як falsy дають `Invalid border radius/width: undefined`. У коді використовуються хелпери **`pdfBorderRadius()`** та **`pdfBorderWidth()`** з `PdfBase.ts` (для нуля підставляється рядок `'0'`).

## 2. Логічна структура сторінки (зверху вниз)

```
┌─────────────────────────────────────────────────────────────┐
│ HEADER: логотип + заголовок + підзаголовок + дата/місто      │
├──────────────────┬──────────────────────────────────────────┤
│ SIDEBAR (~35%)   │ MAIN (~65%)                               │
│                  │                                           │
│ 1. Фото улюбленця│ 4. Деталі тварини (Pet)                   │
│ 2. Власник       │ 5. Текст «Про тварину» (generatedText)    │
│ 3. Поведінка *   │ 6. Страхування / юридичне *               │
│                  │ 7. Референси / контакти *                 │
├──────────────────┴──────────────────────────────────────────┤
│ FOOTER: брендинг + лінія підпису                            │
└─────────────────────────────────────────────────────────────┘
```

\* Блоки **Behavior**, **Legal**, **Reference** рендеряться **тільки якщо** увімкнено «розширену» інформацію (`showAdvancedHealthInfo` або евристика в `getShowAdvancedHealthInfo`). Деталі — у розділі 5.

**Порядок секцій (фіксований у коді):**  
`photo → owner → details → behavior → description → legal → reference`

## 3. Варіанти шаблону (templateType)

У коді є п’ять варіантів: `classic` | `modern` | `compact` | `buddy` | `buddyTest` (останній — експериментальна копія Buddy для прев’ю; PDF використовує ті самі токени, що й Buddy). Вони відрізняються палітрою, відступами сторінки, висотою фото, стилем заголовків секцій і футером. **Buddy** — світло-блакитний тон (`#f8f9ff` / `#eff4ff`), темно-зелений акцент (`#004541`), той самий порядок секцій, що й у інших.

### 3.1 Палітри (референс для Figma)

| Токен | Classic | Modern | Compact | Buddy |
|-------|---------|--------|---------|--------|
| primary | `#0f172a` | `#115e59` | `#44403c` | `#004541` |
| accent | як primary | `#14b8a6` | `#d97706` | `#006b5f` |
| border | `#0f172a` / графіка | `#ccfbf1` | `#a8a29e` | `#bec9c7` |
| light (фони блоків) | `#f1f5f9` | `#f0fdfa` | `#fafaf9` | `#eff4ff` |
| muted | `#64748b` | `#64748b` | `#78716c` | `#64748b` |

### 3.2 Параметри сторінки (референс)

| Параметр | Classic | Modern | Compact | Buddy |
|----------|---------|--------|---------|--------|
| Фон сторінки | `#ffffff` | `#fafafa` | `#fafaf9` | `#f8f9ff` |
| Padding сторінки (pt) | 40 | 36 | 30 | 32 |
| Базовий fontSize (pt) | 10 | 10 | 9 | 10 |
| Висота фото (pt) | 240 | 232 | 210 | 248 |
| Сайдбар: фон / padding / radius | немає | `#f0fdfa`, 8, 6 | `#f5f5f4`, 6, 3 | `#eff4ff`, 10, 8 |

### 3.3 Стиль заголовків секцій

- **Classic:** uppercase, нижня межа 2 pt, колір `primary`.
- **Modern:** ліва смуга 4 pt (`accent`), без uppercase в заголовка.
- **Compact:** uppercase, нижня межа 1 pt **пунктир**, колір `primary` / `border`.

### 3.4 Футер

- **Classic:** повний текст брендингу по центру (uppercase), посилання на сайт.
- **Modern / Compact:** короткий текст `pet-bewerbung.ch` зліва; стиль кольору залежить від шаблону.
- Справа: зона «Підпис» (лінія + підпис).

## 4. Контент по секціях і поля даних

Нижче — **поля об’єкта `PetData`** та ключі перекладів `PdfTranslations` (узагальнено). Підписи в PDF беруться з перекладів UI.

### 4.1 Header (`PdfHeader`)

| Вміст | Джерело |
|-------|---------|
| Логотип | `logoUrl` (data URL JPEG/PNG після завантаження з `public/`), або плейсхолдер |
| Заголовок документа | `t.doc.title` |
| Підзаголовок | `t.doc.subtitle` |
| Дата / місце | `city` + локалізована дата сьогодні, або лише дата |

### 4.2 Фото (`PdfPhoto`)

| Поле | Примітка |
|------|----------|
| `data.photo` | Data URL або blob (перед PDF проходить `preparePdfData`: blob→data URL, webp→jpeg) |
| Плейсхолдер | якщо фото немає — текст з `t.doc.petPhoto` |

Рамка фото залежить від `templateType` (товста/округла/amber тощо).

### 4.3 Власник (`PdfOwnerInfo`)

| Вміст | Поля `PetData` |
|-------|----------------|
| Ім’я | `ownerName` |
| Адреса | `street`, `houseNumber`, `postal`, `city` (через `formatAddress`) |
| Email, телефон | `email`, `phone` |
| QR vCard (опційно) | якщо є `qrUrl` — зображення 75×75 + підписи `t.doc.qrLabel`, `t.doc.qrHint` |

### 4.4 Поведінка (`PdfBehavior`) — умовно

Показується лише якщо `getShowAdvancedHealthInfo(data) === true`.

| Поле | Відображення |
|------|----------------|
| `noiseLevel` | low / medium / high → перекладені лейбли |
| `aloneTime` | число + `h` |
| `activeHours` | рядок, якщо заповнено |
| `behaviorWithChildren`, `behaviorWithPets` | good / neutral / bad → переклади |

### 4.5 Деталі тварини (`PdfDetails`)

| Поле | Примітка |
|------|----------|
| `name` | акцентним шрифтом |
| `breed` | |
| `gender`, `age` | через хелпери форматування |
| `weight` | |

### 4.6 Опис (`PdfDescription`)

| Поле | Примітка |
|------|----------|
| `generatedText` | основний текст; якщо порожній — fallback з `t.ui.noDescription` |

### 4.7 Страхування та юридичне (`PdfLegal`) — умовно

Той самий прапорець, що й для Behavior. Блок у «коробці» (фон `colors.light`, бордер).

| Поле | Тип |
|------|-----|
| `chipId` | текст |
| `insuranceProvider` | текст |
| `vetName`, `vetPhone` | об’єднання через ` · ` |
| `isNeutered` | так/ні |
| `hasVaccination`, `hasRegistration` | так/ні |
| `willingToPayDeposit` | так/ні |
| `medicalConditions` | окремий підблок зверху з роздільником, якщо заповнено |

### 4.8 Референси (`PdfReference`) — умовно

Показується, якщо увімкнено advanced **і** є хоча б одне з: попередній орендодавець, екстрений контакт, другий екстрений контакт.

Колонки: попередній орендодавець (ім’я, тривалість, телефон, email) та екстрений контакт (ім’я, стосунки, телефон). Опційно блок `secondaryEmergencyContact`.

Візуально — окремий кольоровий блок (синій / teal / amber залежно від шаблону).

### 4.9 Footer (`PdfFooter`)

- Текст брендингу з `t.doc.footer` (або дефолт).
- Посилання: `https://pet-bewerbung.ch`
- Підпис: `t.doc.sign`

## 5. Умовна видимість блоків

Щоб дизайн макету враховував «короткий» і «повний» CV:

1. **`getShowAdvancedHealthInfo(data)`**  
   Якщо `false`: секції **Behavior**, **Legal**, **Reference** **не** потрапляють у PDF (у сайдбарі зникає Behavior; у main — зникають Legal і Reference, якщо немає даних референсів).

2. **Reference** додатково ховається, якщо немає жодного релевантного поля.

## 6. Обмеження та ризики для нового макету

1. **Зображення:** react-pdf краще працює з **JPEG/PNG**; WebP конвертується перед вставкою.
2. **Складна верстка:** flex, border, background — так; CSS як у браузері — частково.
3. **Довгий текст:** `generatedText` і медичні поля можуть розтягувати сторінку — закладати перенос або зменшення шрифту в специфікації.
4. **QR:** фіксований розмір 75×75 pt у поточній реалізації.
5. **Локалізація:** усі видимі підписи йде з об’єкта перекладів — новий шаблон не повинен «вшивати» німецькі рядки в код без ключів.

## 8. Чеклист для дизайнера (що надати перед кодом)

- [ ] Макет **A4** з усіма секціями в **повній** і **скороченій** версії (без advanced-блоків).
- [ ] Окремо стан **без фото** та **з фото**.
- [ ] Таблиця кольорів (primary, accent, фон, текст, бордери) для кожного з трьох варіантів або для одного нового варіанту.
- [ ] Типографіка: розміри заголовків / body / captions (у pt або px з прив’язкою до A4).
- [ ] Поведінка футера та хедера при довгому контенті (якщо потрібен повторюваний header/footer на 2+ сторінках — це **окрема** задача в react-pdf).
- [ ] Узгодженість з **перекладами** (DE/EN/FR/IT/RM) — довгі рядки в футері/хедері.
